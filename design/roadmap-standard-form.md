# 다음 단계: HWP 기본 + 지원서 없는 공고용 표준 지원서

## 상태

- 결정일: 2026-10-03
- 결정자: 사용자
- 근거: `otr-form-survey-2026-10.md` (OTR 공고 189건 종합 조사)

## 근거 요약

| | 189건 중 | 비율 |
|---|---:|---:|
| 지원서 파일이 있는 공고 | 71 | 37.6% |
| └ 그중 HWP | 56 | 지원서 있는 공고의 78.9% (전체의 29.6%) |
| └ DOCX·DOC·XLSX·외부 링크 | 15 | 지원서 있는 공고의 21.1% (DOCX 8, DOC 3, XLSX 2, 외부 2) |
| **지원서 파일이 없는 공고** | **118** | **62.4%** |

- 지원서 없는 공고(조사 A 59건) 대부분은 **프로필을 이메일로** 받는다(30건, "프로필" 언급 없는 이메일 접수 14건). "자유 양식"을 명시한 글은 2건.
- 지원서가 있으면 높은 확률로 HWP다. 지금 엔진이 그 대부분을 처리한다.

## 확정 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | **HWP를 기본 형식으로 유지한다.** 지원서가 첨부된 공고는 지금의 공고 링크 흐름(원본 업로드 → 정의 → 테스트 → 공개)으로 처리한다 | 지원서 있는 공고의 약 80%가 HWP이고, 엔진·검증·운영 도구가 이미 있다 |
| 2 | **지원서가 없는 공고에는 예술in 표준 지원서를 쓴다.** 표준 지원서 HWP 양식은 우리가 하나 정해서 만든다 | 공고의 약 60%가 여기에 해당한다. 새 문서 엔진 없이 지금 HWP 흐름을 그대로 쓸 수 있다 |
| 3 | **표준 지원서의 항목은 HWP 지원서들의 정의 JSON을 모아, 자주 나오는 항목으로 정한다** | 실제 공연사들이 묻는 것을 근거로 한다. 정의 JSON이 쌓일수록 표준이 단단해진다 |
| 4 | **표준 지원서는 "기본 항목 + 공고별 추가 항목"으로 만든다.** 운영자는 지원서 없는 공고를 열 때 기본 지원서에서 시작해, 공고 본문의 요구사항(지원 역할, 일정, 메일 제목 형식 등)을 추가 항목으로 쉽게 붙일 수 있어야 한다 | 지원서 없는 공고도 본문에 고유한 요구가 있다. 공고마다 JSON 전체를 새로 쓰지 않게 한다 |
| 5 | **표준 지원서를 쓰는 공고에서는 배우가 더 자유롭게 고치고 항목을 더할 수 있어야 한다** | 정해진 양식이 없는 공고는 배우가 자기 지원서를 내는 것과 같다. 고정된 칸만으로는 부족하다 |

| 보류 | DOC·XLSX·외부 링크·온라인 폼 | 약 6% | 각 1~2% 수준. 필요하면 표준 지원서로 대신하거나 변환으로 처리 |

## P2에서 정할 것 (설계 전 질문)

> 2026-10-03 결정됨: `standard-form.md`. 아래는 결정 전 질문 기록이다.

- **표준 지원서 HWP 모양**: 사진 칸 수, 인적사항 묶음, 경력 표 줄 수, 자기소개, "추가 질문" 영역의 크기와 모양.
- **추가 항목을 문서에 담는 방법**:
  1. 표준 양식에 "추가 질문" 칸을 미리 N줄 두고 차례로 채운다. 지금 엔진 그대로 가능하지만 줄 수가 고정된다.
  2. HWP 표에 줄을 늘리는 기능을 엔진에 추가한다. 유연하지만 hwplib 작업이 필요하다.
  3. 추가 질문은 큰 칸 하나에 "질문: 답" 글로 이어 쓴다. 단순하지만 표 모양이 약하다.
- **배우의 자유 수정 범위**: 추가 항목의 이름까지 고칠 수 있게 할지, 내용만 쓰게 할지, 경력 줄을 더할 수 있게 할지, 안 쓰는 칸을 숨길지.
- **정의 형식**: 표준 지원서를 가리키는 방법(`"base": "standard-v1"` 같은 참조)과 공고별 추가 항목을 어떻게 적을지. 기존 공고 정의와 같은 검증·테스트·공개 흐름을 유지한다.
- **운영자 화면**: 지원서 없는 공고를 "표준 지원서로 시작" 버튼으로 열고, 추가 항목을 JSON 대신 간단한 입력으로 붙일 수 있게 할지.
- **결과물**: HWP와 PDF를 모두 주되, 이메일 프로필 제출이 많으므로 PDF를 먼저 보이게 할지.

## 지키는 원칙

- 서비스는 칸이나 항목을 자동 추론하지 않는다. 표준 항목과 추가 항목은 운영자가 정하고(에이전트 초안 가능), 검증·테스트를 거쳐 공개한다.
- 배우 정보는 지금처럼 저장하지 않는다. 생성용 작업 파일은 30분 뒤 삭제되고, 입력값은 브라우저에만 있다.
- OTR 자동 수집, AI 파싱, 배우 계정·장기 프로필 저장은 이번에도 범위 밖이다.
