# P2 설계: 표준 지원서 + "기본 + 추가"

`roadmap-standard-form.md`의 P2다. 지원서 파일이 없는 공고(약 60%)에 쓸 예술in 표준 지원서와 그 운영 흐름을 정한다. 항목의 근거는 `standard-items.md`(P1)다.

## 상태

- 결정일: 2026-10-03, 결정자: 사용자
- 표준 지원서 v1 모양: 2026-10-03 사용자 확인으로 확정(아래 "표준 지원서 v1").
- 진행: 구현 순서 1~3과 제출 안내(결정 11)까지 완료. 다음은 4(운영자 화면), 5(PDF 먼저).

## 확정 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | **추가 항목은 표에 줄을 끼워 넣는다.** 항목 하나가 표 한 줄(라벨 + 값 칸)이다 | 빈 줄이 남지 않고 표 모양이 그대로다. 아래 "확인한 것"대로 엔진을 새로 만들 필요가 없다 |
| 2 | **배우는 경력 줄을 더하고, 자기 항목(이름 + 내용)을 더할 수 있다.** 안 쓴 칸 지우기는 하지 않는다 | 정해진 양식이 없는 공고라 배우의 프로필과 같다. 줄은 배우의 작업 사본에만 생기고 공유 원본은 그대로다 |
| 3 | **표준 지원서 HWP는 우리가 만든다**(rhwp `scaffold`로 만든 합성 양식). 우리 양식이라 저장소에 올릴 수 있다 | 실제 공고 원본이 아니고, 만드는 과정을 다시 할 수 있다 |
| 4 | **운영자는 화면에서 고른다.** "표준 지원서로 시작" → 추가 항목 목록에서 고르거나 직접 적기 → 서버가 그 공고의 원본 HWP와 정의 JSON을 만든다 → 테스트 → 공개 | 지원서 없는 공고마다 JSON 전체를 쓰지 않게 한다. 검증·테스트·공개·버전 고정은 지금 흐름 그대로다 |
| 5 | 결과물은 HWP와 PDF를 모두 주고, 표준 지원서 공고는 **PDF를 먼저** 보인다 | 지원서 없는 공고는 대부분 프로필을 이메일로 받는다(`otr-form-survey-2026-10.md`) |

## 확인한 것 (2026-10-03, 합성 양식으로)

`tools/rhwp`(v0.8.6)의 편집 명령으로 표 줄을 다룰 수 있다.

- `edit insert-row --table T --row R [--below]`: 줄을 끼운다. 병합 칸 안에 끼우면 병합 범위가 함께 늘어난다(경력 칸 3줄 → 4줄 확인).
- 새 줄은 칸이 나뉜 채로 생긴다. `edit merge-cells`로 값 칸을 합치고 `edit set-cell`로 라벨을 쓴다.
- `edit delete-row`: 줄을 지운다.
- 이렇게 고친 파일을 hwplib으로 열고 저장해도 깨지지 않는다. rhwp PDF로 그려 보면 끼운 줄이 이웃 줄과 같은 높이·선으로 나온다.
- **한글 앱에서는 아직 열어 보지 않았다.** 구현 전에 한글로 한 번 확인한다.

## 표준 지원서 v1

A4 2쪽, 표 4개. 1쪽은 인적사항·지원 정보, 2쪽은 경력·사진(쪽 나눔 고정).

| 표 | 내용 | 줄 |
|---|---|---|
| 0 인적사항 | 이름·생년월일 / 연락처·이메일 / 성별(`남(  )  여(  )`에 V 표시)·거주지 / 키·몸무게 / 학력 / 특기, 오른쪽에 대표 사진 1칸(6줄 병합, 40×54mm = 3:4) | 6 |
| 1 지원 정보 | 지원 배역 / 현재 출연 작품 / 참여 불가 일정 / 자기소개·지원동기(큰 칸) | 4 |
| 2 출연 경력(최근순) | 머리줄 작품명·역할·기간·공연장·단체·제작사 + 빈 줄 10 | 11 |
| 3 프로필 사진 | 이름표 없는 사진 2칸(각 74×98.5mm, 3:4) | 1 |

- 항목은 P1 기본 12개(이름, 연락처, 주소, 생년월일, 사진, 학력, 이메일, 키, 몸무게, 특기, 성별, 경력)와 기본 질문 4개(지원 배역, 현재 출연 작품, 참여 불가 일정, 자기소개·지원동기)다.
- 사진은 모두 3칸이다(대표 1 + 프로필 2). 대표 사진만 필수다. 프로필 사진에는 상반신·전신 같은 제한을 두지 않는다.
- 2026-10-03 사용자 확인 뒤 고침: 프로필 사진 3칸(상반신·전신·자유) → 2칸, 대표 사진 칸을 3:4로, 성별을 빈 칸 → `남(  )  여(  )` 체크로. 인적사항에도 사진이 있어 프로필 3칸은 흐름이 어색했다.
- 공고 제목 문단(`{공고 제목}`)은 공고마다 바꿔 넣는다.
- 파일: `backend/src/main/resources/standard/standard-v1.hwp`와 기본 정의 `standard-v1.definition.json`. HWP는 `bash tools/standard-form/build.sh`로 다시 만든다(rhwp `scaffold` → 열 너비·병합·쪽 나눔 → hwplib으로 줄 높이). 같은 스크립트를 다시 돌리면 같은 양식이 나온다.

## 구현 순서

1. ✅ **표준 지원서 자산**: 표준 HWP와 기본 정의(항목·출력)를 저장소에 두고, 만드는 방법을 옆에 적는다. 줄 표 `rows` 항목·출력과 줄 끼우기(`RowInserter`)도 여기서 만들었다. 배우 화면에는 줄마다 열 입력 카드와 "줄 더하기"가 있다.
2. ✅ **공고 원본 만들기**: 공고 설정(`"base": "standard-v1"`, `title`, `roles`, `drop`, `extras`, `help`, `submission`)을 저장하면 `StandardForms`가 그 공고의 HWP(지원 정보 표에 추가 항목 줄 끼우기·뺄 줄 지우기·공고 제목·라벨)와 전체 정의를 만든다. 설정은 `spec.json`으로 남아 운영자 화면에 보이고 백업에 들어간다. 이후는 지금의 검증·테스트·공개와 같다. 추가 항목 목록은 `standard-v1.extras.json`. 제출 안내(`submission`)는 모든 공고의 정의에 쓸 수 있고, 배우 완료 화면에 받는 곳·채운 메일 제목·마감과 복사 버튼, 메일 쓰기가 나온다.
3. ✅ **배우 자유**: 경력 줄 더하기와 자기 항목("더 알리고 싶은 것", `rows` 2열, `formRows` 0)은 1에서 `rows`로 함께 됐다. 줄은 생성할 때마다 작업 사본의 임시 파일에만 끼운다.
4. **운영자 화면**: "표준 지원서로 시작", 추가 항목 목록 고르기와 직접 적기. 지금은 공고 설정 JSON을 정의 칸에 붙여넣는다(AI가 공고 본문으로 써 줄 수 있다: `form-definition-guide.md`).
5. **배우 화면**: 경력 줄 더하기, "항목 더하기", 완료 화면에서 PDF 먼저 보이기.

## 줄 끼우기 동작

- 배우가 양식 줄보다 많이 쓰면, 생성할 때 원본을 임시로 복사해 rhwp `edit insert-row`로 마지막 양식 줄 아래에 줄을 끼운다. 공유 원본과 작업 원본은 그대로라 다시 만들 때마다 빈 양식에서 시작한다.
- 새 줄은 칸이 나뉜 채로 생기므로, 복사한 줄에서 옆으로 병합돼 있던 칸을 `edit merge-cells`로 다시 합친다(22369처럼 한 줄이 한 칸인 경력 줄도 늘어난다).
- 끼운 뒤 표의 줄 수와 새 줄의 칸 수를 확인한다. 위아래로 병합된 칸이 걸친 줄, 표 안에 표가 있는 양식(rhwp와 hwplib의 표 번호가 달라짐)은 오류로 알리고, 운영자 테스트 생성에서 드러난다.
- 같은 표에서 끼운 줄 아래의 출력 칸은 서버가 밀어서 쓴다. 정의의 주소는 원본 그대로다.

## 최대 입력 검증 (2026-10-03)

표준 지원서 v1에 입력을 바꿔 가며 테스트 생성하고, rhwp 쪽 배치(`dump-pages`)와 PDF로 확인했다. 한글 앱에서는 아직 보지 않았다.

| 입력 | 쪽 | 쪽 구성 |
|---|---:|---|
| 최소(이름·연락처·경력 1줄) | 2 | 1쪽 인적사항·지원 정보 / 2쪽 경력·사진 |
| 경력 10줄(짧게, 또는 칸마다 두 줄로 꺾임) | 2 | 같음 |
| 경력 20줄 | 3 | 사진이 3쪽으로 |
| 경력 20줄 + 자기 항목 3개 + 자기소개 600·1500자 | 4 | 자기소개가 2쪽으로 이어지고 경력 3쪽, 사진 4쪽 |
| 모든 칸 최대 글자(경력 칸마다 40자 등) | 5 | 경력 표가 3~5쪽에 나뉨 |
| 최대 입력 뒤 같은 작업을 최소 입력으로 다시 생성 | 2 | 끼운 줄 없이 원래 양식으로 돌아옴 |

찾아서 고친 것:

- **표 겹침**: 경력 줄이 늘어 사진 표가 2쪽에 들어가지 못하면, rhwp가 사진 표를 다음 쪽으로 넘기지 않고 경력 표 위로 끌어올려 그렸다(PDF가 깨짐). 생성 뒤 rhwp 쪽 배치를 읽어, 넘친 쪽의 마지막 표(바로 위 짧은 제목 포함)에 문단의 "쪽 나누기"를 켜고 다시 저장한다(`TableFlow`, 최대 3번). rhwp는 읽기만 하고 수정은 hwplib으로 한다. rhwp로 사진이 든 파일을 다시 저장하면 그림 데이터가 두 벌이 되기 때문이다.
- **빈 쪽**: 경력 제목 앞 빈 문단 2개가 1쪽이 꽉 찰 때 혼자 다음 쪽으로 넘어가 빈 쪽을 만들었다. 재생성 스크립트에서 지웠다.

남은 것:

- 자기소개가 길면(자기 항목 3개일 때 약 400자부터) 1쪽을 넘어 2쪽에 꼬리만 남고, 경력은 쪽 나누기 때문에 3쪽에서 시작한다. 자기소개 글자 수 상한(지금 1500)을 줄일지, 경력 앞 쪽 나누기를 둘지는 실제 사용을 보고 정한다.
- 표 겹침 점검은 rhwp가 있는 서버에서만 한다. 한글 앱은 쪽을 스스로 다시 나누므로 원래 겹치지 않을 것으로 본다.
