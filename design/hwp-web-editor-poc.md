# HWP 웹 직접 편집 가능성 시험

2026-10-04. 결론: **표 안의 지원동기 값을 다른 칸으로 옮기고 안내문을 삭제한 뒤 실제 HWP로 저장하는 것은 가능했다. 현재 서비스에 바로 도입할 준비가 끝난 것은 아니다.**

## 시험 범위

22389의 원본 HWP는 로컬에 없었다. 운영 사이트의 원본·공개 버전·배우 작업을 수정하지 않았다. 저장소의 합성 양식 `sample-notice.hwp`로 다음 상태를 재현했다.

- 제목 칸에 `지원동기`와 `예시 지원동기: 함께 무대에 서고 싶습니다.`가 함께 있음.
- 바로 아래의 큰 칸에 빨간 안내문 세 문장이 있음.
- 주변 이름·경력·사진 등의 표와 병합 구조가 있음. 사진은 실제 사진이 아닌 `사진`이라는 표시다.

시험 도구는 공식 npm `@rhwp/editor@0.8.6` SDK와 공식 rhwp Studio 웹 편집기다. SDK는 기본적으로 `https://edwardkim.github.io/rhwp/`를 iframe에 불러온다. 별도 localhost 시험 화면에서 합성 HWP 바이트를 전달했고, 서버의 생성 코드는 변경하지 않았다. 이번 시험은 외부 Studio를 사용했으며, 실제 배우 문서를 외부 Studio에 전달하는 운영 결정을 내린 것은 아니다.

## 실제 수행과 결과

브라우저의 **찾아 바꾸기** 화면에서 제목 칸의 답변을 지우고, 하단 안내문의 첫 문장을 같은 답변으로 바꿨으며, 나머지 두 안내 문장을 지웠다. 드래그 이동이나 잘라내기·붙이기의 성공을 입증한 시험은 아니다.

| 확인 | 결과 | 근거 |
|---|---|---|
| 제목 칸에서 답변 제거 | 통과 | 저장본의 제목 칸 원문은 `지원동기` |
| 아래 칸에 답변 배치 | 통과 | 저장본의 아래 칸 원문은 예시 지원동기 문장 |
| 빨간 안내문 세 문장 삭제 | 통과 | HWP 재파싱·격자 추출에서 안내문 없음 |
| 실제 HWP 저장 | 통과 | 5,120바이트, 매직 `D0-CF-11-E0-A1-B1-1A-E1` |
| 다른 엔진으로 재읽기 | 통과 | 서비스의 hwplib 1.1.11로 1구역·19칸 읽음 |
| 나머지 칸 내용·병합 유지 | 통과 | 수정한 두 칸 외 17칸의 텍스트·행/열 병합 격자가 원본과 동일 |
| 저장본 다시 열기 | 통과 | 웹 편집기 재로드 및 자체 검증 `recovered: true`, 1쪽→1쪽 |
| 현재 서버의 PDF 변환 경로 | 통과 | CLI rhwp로 PDF 1쪽 생성 |
| 이동한 답변을 검은 글씨로 정리 | 미완료 | 아래 칸의 빨간 글씨 서식을 상속함. 서식 대화상자 시험으로 실제 값의 색 변경을 확정하지 못함 |
| 자유 선택·잘라내기·붙이기 | 미확인 | 자동화 조작에서 일관된 결과를 확보하지 못함. 편집기 자체의 결함으로 단정하지 않음 |
| 사진·복잡한 실제 양식의 보존 | 미확인 | 실제 사진·22389 원본은 이번 합성 시험에 없음 |
| 한컴 한글에서 열기 | 미확인 | 웹·CLI·hwplib 검증만 수행 |
| 모바일 실제 기기와 한글 조합 입력 | 미확인 | PC Chrome의 390×844 화면 크기만 확인 |

모바일 100% 배율에서는 문서의 일부만 보였고, 쪽 맞춤에서는 글자가 작았다. 지원동기 삭제·이동의 모바일 터치·키보드 사용성을 통과했다고 말할 수 없다.

SDK의 `exportHwp()`는 바이트를 돌려줄 뿐 저장 완료를 확정하지 않는다. 시험 중 미저장 문서 복구본 안내가 실제로 나타났다. 공식 SDK 문서에 맞춰 시험 호스트의 저장 성공 후 `notifySaved()`를 호출하도록 보완했다. 해당 합성 문서의 복구 후보는 삭제했다. 운영 도입 시 IndexedDB 자동복구·보관·삭제 정책을 별도로 결정하고 시험해야 한다.

## 도입 선택지

| 방향 | 장점 | 남는 작업 | 판단 |
|---|---|---|---|
| 현재 미리보기에 칸 단위 직접 편집 추가 | 입력 화면이 단순하고 기존 hwplib 저장 경로를 이용할 수 있음 | 칸 선택·텍스트 삭제·이동·서식 처리 API와 화면, 저장·미리보기 갱신 | 이번 두 사례와 배우 모바일 흐름에 우선 추천 |
| rhwp 전체 웹 편집기 추가 | 텍스트와 표를 문서처럼 편집할 수 있는 기반이 이미 있음 | 자체 호스팅·저장 연동·원본/JSON 일치·복구 정책·서식·사진·모바일·호환성 검증 | 운영자의 PC 편집부터 제한적으로 검토 |

칸 단위 직접 편집도 현재 구현된 기능은 아니다. 기존 배우 미리보기는 SVG 이미지와 입력 항목 수정 버튼이고, 문서의 임의 칸을 지우거나 출력 위치를 옮길 수 없다.

운영자 편집과 배우 편집은 저장 의미가 다르다.

- **운영자가 테스트 완성본만 수정하면 다음 배우에게 같은 오류가 다시 생긴다.** 재사용할 수정은 양식 정의의 출력 위치·삭제 규칙 또는 새 원본 버전에 반영해야 한다. 표 행·열을 바꾸면 칸 목록과 JSON 참조도 다시 검증해야 한다. 공개 원본을 덮어쓰는 방식은 피한다.
- **배우의 완성본 수정은 그 배우의 작업 파일에만 반영한다.** HWP 다운로드·PDF·메일 공유가 모두 같은 수정본을 사용해야 한다. 이후 기존 입력값으로 재생성하면 직접 편집이 사라질 수 있으므로 재생성 규칙을 정해야 한다.

전체 편집기를 도입할 경우 현재 보안 헤더 그대로 외부 iframe을 붙이는 것은 되지 않는다. `SecurityHeadersFilter`의 자체 출처 정책·프레임 차단과 WASM/worker 실행 조건을 확인해야 한다. 편집기 경로만 필요한 범위로 구성하고 기존 API·미리보기 정책을 일괄 해제하지 않는다. 버전이 바뀔 수 있는 공식 데모 URL을 운영 의존성으로 삼는 대신, 검증한 Studio와 WASM·글꼴을 자체 호스팅하는 방향을 검토한다.

## 다음 시험의 통과 기준

1. 22389의 실제 원본·현재 완성본으로 답변 이동, 원문 안내 삭제, 검은 글씨, 한글 앱 열기 확인.
2. 사진과 병합 표가 다른 대표 HWP 양식에서도 편집→HWP 재읽기→서버 PDF→다운로드 결과를 대조.
3. 운영자 수정이 새 테스트·공개 버전에 재사용되는지 확인. 배우 작업에서는 공용 양식이 변하지 않는지 확인.
4. 실제 iPhone Safari·Android Chrome에서 한글 조합, 선택·삭제, 키보드 표시, 실행 취소와 저장을 확인.
5. 저장 실패·새로고침·30분 만료·직접 편집 후 재생성·임시 복구본 삭제를 확인.
