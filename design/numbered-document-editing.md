# 완성 지원서의 번호 기반 직접 수정

2026-10-04. 사용자 승인에 따라 **완성본 직접 수정 + 확인 후 입력값으로 재생성(A)**을 구현했다. 로컬 검증을 마쳤으며 아직 커밋·운영 배포하지 않았다. 이전 독립 편집기 시험은 [hwp-web-editor-poc.md](hwp-web-editor-poc.md)를 참고한다.

## 배우가 사용하는 흐름

| 순서 | 조작 | 결과 |
|---|---|---|
| 1 | 완료 화면의 **확대** | 확대 문서 위에 `1-3` 같은 번호 표시. 별도 편집 모드 전환 없음 |
| 2 | 확대 문서에서 고칠 칸을 누르기 | 현재 글을 여는 수정 시트 |
| 3 | 글 수정 또는 **글 비우기** | JSON에 없는 빈칸·라벨·안내문도 수정 |
| 4 | **글을 다른 번호로 옮기기** | 원래 글의 일부/전체와 받을 번호 입력. 대상의 기존 글을 확인하고 교체에 동의 |
| 5 | **적용하고 미리보기** / **옮기고 적용** | 해당 배우의 HWP 수정·재렌더링. 선택한 영역 강조 |
| 6 | 완료 화면에서 저장·메일 공유 | 최신 HWP/PDF 사용. 번호는 파일에 들어가지 않음 |

번호는 현재 문서의 시각적 순서로 매긴다. 같은 영역이 여러 쪽에 걸치면 같은 번호로 연결한다. 새 렌더링으로 위치가 바뀌면 번호도 다시 계산하므로 영구 주소로 쓰지 않는다.

2026-10-06 완료 화면의 별도 직접 수정 버튼과 번호 입력 도구를 제거했다. 확대 화면에서 바로 수정 칸을 누른다. 확대 화면의 닫기 바는 화면 상단에 고정하며 문서만 가로·세로로 스크롤한다.

표 밖의 일반 제목·본문 문단도 번호가 있으면 수정할 수 있다. 표 입력은 기본적으로 검정·보통 굵기로 맞추며, 제목·기존 라벨 서식을 유지하려면 서식 선택을 해제한다. 이동 시 원래 영역의 서식은 유지하고 받을 영역에는 입력 서식을 적용한다.

## 지원동기와 빨간 안내문 사례

지원동기 제목 칸에 제목과 답변이 있고 아래 칸에 빨간 안내문이 남았다면, 제목 칸에서 답변 부분만 아래 번호로 옮긴다. 아래의 기존 안내문을 교체한다는 확인을 거쳐 한 번에 두 영역을 수정한다. 제목은 남고 답변은 아래 칸에 검정·보통 굵기로 들어간다. 다른 안내문은 각각 선택해서 비울 수 있다.

문서의 글을 옮기는 기능이다. 표의 행 추가·크기 변경·본문 자유 배치·사진 편집 기능은 아니다. 지원서의 1쪽 제한이나 빨간 글 자동 삭제를 판정하지 않는다.

## 재생성 정책 — 승인된 A

- 뒤로 가면 처음 입력값과 사진을 고칠 수 있다. 직접 수정한 내용은 입력 항목에 자동 역반영하지 않는다.
- 직접 수정한 뒤 **지원서 만들기**를 누르면 글 수정·삭제·이동이 사라진다는 확인창을 먼저 보여준다.
- **수정본 유지**는 생성 요청을 보내지 않는다. **수정한 지원서로 돌아가기**로 기존 수정본을 확인·저장할 수 있다.
- **확인하고 다시 만들기**는 작업의 원본 사본과 현재 입력값·사진으로 재생성한다. 직접 수정 기록을 다시 적용하지 않는다.
- 공유 원본·운영자 정의·공개 버전은 변경하지 않는다. 배우의 직접 수정으로 다른 배우의 출력 오류가 해결되는 것은 아니다.

## 권한·충돌·저장

| 항목 | 구현 |
|---|---|
| 수정 권한 | 생성 응답의 `X-Document-Edit-Token`. 브라우저 메모리에만 보유. 작업 ID 조회·다운로드·이어받기로는 발급하지 않음 |
| 기존 작업 재생성 | 공개 생성 요청에 작업 ID와 수정 토큰을 함께 보낸다. 토큰 없이 ID만 보내면 새 작업 생성. 잘못된 토큰은 403. 운영자 테스트는 별도 관리자 인증으로 재사용 |
| 조회/수정 | `GET` / `POST /api/documents/{id}/editing`, 수정 토큰 헤더 필수 |
| 화면 버전 | HWP SHA-256 `revision`. 시트를 열었을 때 버전으로 수정. 오래된 화면은 409 충돌 후 새 미리보기 확인 |
| 요청 | 현재 표시 가능한 영역 1~2개, 영역당 20,000자 이하. 이동은 서로 다른 두 영역의 교체 |
| 쓰기 | 작업별 잠금 → 임시 HWP → 재파싱해 글 일치 검사 → 렌더링 → 만료 재검사 → 원자적 교체 |
| 실패 | 후보 렌더 실패·오래된 버전·권한 오류는 기존 HWP 보존. 임시 후보와 렌더 파일 정리 |
| 결과 갱신 | SVG·좌표·PDF 캐시 무효화, 브라우저 HWP 교체. PDF는 새 HWP 파일 객체와 연결하여 이전 PDF 공유 차단 |
| 수명 | 최초 작업 생성부터 30분. 수정은 연장하지 않음. 배우 글·사진·토큰·작업 ID는 로그·분석에 넣지 않음 |

수정 시트와 확대 화면에서는 배경 조작·스크롤을 막고 키보드 초점을 시트 안에 둔다. 적용 중에는 취소·중복 적용을 막는다. 편집 정보를 읽지 못하면 오류와 다시 불러오기, 읽기 전용 미리보기·다운로드를 제공한다.

## 지원 범위와 제한

- **한 구역의 최상위 표와 일반 본문**을 대상으로 한다. 그림·체크 컨트롤 등 글 외 컨트롤이 든 영역은 번호를 제공하지 않는다. 구역/단 정의는 보존한다.
- 중첩 표·여러 구역·글상자 안 표가 있으면 문서 전체의 직접 편집을 제한한다. 번호와 화면 위치를 잘못 연결해 다른 칸을 고치는 일을 피하기 위해서다.
- 글상자·머리말·꼬리말·이미지 속 글자·사진 자체는 직접 수정하지 못한다. 사진·입력 항목 변경은 입력 화면에서 재생성한다.
- 새 브라우저나 새로고침 후에는 수정 토큰과 입력값이 없어, 이어받기 링크로 완성 파일 조회·저장만 가능하다.
- 복잡한 원본과 실제 한글 앱의 문서 배치는 별도 검증이 필요하다. 모든 HWP를 편집할 수 있다는 의미가 아니다.
