# 프로젝트 규칙 — 사람과 AI 공통

이 저장소에서 일하는 사람과 AI(Claude Code, Codex, 웹 채팅 등)가 함께 지키는 규칙이다. 루트의 `CLAUDE.md`, `AGENTS.md`는 각 도구가 자동으로 읽는 위치라 거기에 두고, 내용은 이 문서를 가리키기만 한다.

## 1. 작업 방식

- 대화와 문서는 한국어로 쓴다.
- **문서는 `design/`에 둔다.** 예외: 루트 `README.md`(실행·배포 안내), 도구용 진입 파일(`CLAUDE.md`, `AGENTS.md`), 테스트 리소스 옆 설명(`backend/src/test/resources/forms/README.md`), 외부 도구 번들과 함께 보존하는 `LICENSE`·`UPSTREAM.md`.
- 지금 구조와 관계가 멀어진 문서는 남겨 두지 않고 지운다. 남길 문서는 README의 "구성" 목록에 올린다.
- **커밋·푸시·배포는 요청이 있을 때만 한다.** 작업을 마치면 기본으로 커밋 메시지만 제안한다(한국어, 첫 줄 `feat:`/`fix:`/`docs:`/`chore:` + 요약, 본문에 이유와 바뀐 것).
- 다른 저장소(예: `2026-yesulin`), 운영 서버 설정(Railway 변수 등)은 고치지 않고 방법만 안내한다.
- 설계 판단이 필요한 것(구조, 저장 방식, 공개 인터페이스)은 선택지와 추천을 보여주고 사람이 정한다.

## 2. 지키는 원칙

- **서비스 안에는 AI도 자동 추론도 없다.** 공고 링크는 운영자가 정한 양식 정의대로만 동작한다. 팀원의 외부 AI가 제공받은 OTR 본문·이미지(이미지 읽기/OCR)·지원서로 JSON 초안과 요구사항 반영표를 만들고, 운영자가 검토·등록·테스트·공개한다. 서비스의 OTR 자동 수집이나 접수 완료 보장이 아니다.
- **배우 정보는 저장하지 않는다.** 입력값은 브라우저에만 있고, 생성용 작업 파일(사진·완성본)은 서버 작업공간에서 30분 뒤 지워진다. 로그·분석에는 이름, 답, 완성 파일 이름, 작업 ID를 남기지 않는다.
- **저장소는 공개다.** 실제 지원자 정보, 실제 사진, 운영자 토큰, 실제 공고 원본을 커밋하지 않는다. 테스트는 합성 양식(`sample-notice.hwp`)과 그린 사진을 쓴다.
- 범위 밖(별도 결정 전까지): OTR 자동 수집, 서비스 안의 AI 파싱, 배우 계정·장기 프로필 저장, 공연사 심사 기능.

## 3. 양식 정의 규칙(`form-definition-guide.md`)은 쓰면서 고친다

정의 JSON은 운영자와 팀원이 각자 AI와 대화해서 만든다. 그래서 규칙 문서가 곧 모두가 같은 결과를 내는 기준이다.

- 정의 JSON을 쓰거나 고칠 때는 `design/form-definition-guide.md`를 먼저 읽고 따른다.
- **"이 부분 JSON을 이렇게 해줘"라는 고침 요청을 받으면** JSON만 고치고 끝내지 않는다. 가이드의 "고쳐 달라는 요청을 받았을 때" 절차대로 고침을 분류한다(이 공고만의 판단 / 규칙 부족·오류 / 서비스 한계).
  - 규칙 부족·오류면 **같은 작업에서 가이드도 고친다**: 해당 규칙 문장, 사례집 한 줄, 변경 기록 한 줄.
  - 파일을 직접 못 고치는 AI는 붙여넣을 수정안을 준다. 받은 사람이 반영해 커밋한다.
  - 서비스 한계면 가이드의 "알려진 한계"에 적고 개발 요청으로 넘긴다.
- 기존 규칙과 부딪히는 고침은 말없이 바꾸지 않고 어느 쪽이 맞는지 묻는다.
- **코드와 가이드는 같이 움직인다.** 정의 형식·검증·출력 규칙을 바꾸는 코드 변경(`backend/src/main/java/kr/yesulin/actor/form/`, 프런트 `frontend/src/form/fileName.ts` 등)은 같은 변경에서 `form-definition-guide.md`와 `notice-forms.md`를 고친다. 가이드가 서버 검증과 어긋나면 서버가 맞고 가이드를 고친다.
- 가이드의 예시 JSON은 실제로 서버 검증을 통과한 것만 싣는다.

## 4. 코드 작업

- 기존 코드의 문체·이름·주석 밀도를 따른다. 파일은 책임별로 나누고, 한 파일이 250줄(빈 줄·주석 제외)을 넘지 않게 한다.
- 바꾼 동작은 테스트로 고정한다. 확인 명령:
  - 백엔드: `backend`에서 `gradlew test` (공고 링크는 `kr.yesulin.actor.form`)
  - 프런트: `frontend`에서 `npm test`, `npm run build`, `npm run lint`
- 화면이 바뀌면 브라우저로 직접 확인하고, 문서 생성이 바뀌면 실제 HWP를 만들어 `rhwp export-tables`로 칸 내용을 확인한다.
- 실제 기기·한글 앱에서 확인하지 못한 것은 결과 보고에 그렇게 적는다.

## 5. 외부 에이전트 스킬

- Codex와 Claude Code 모두 `design/agent-skills.md`를 읽고, 거기에 정한 조건에 따라 `design/skills/`의 원본 스킬을 적용한다.
- 완료·수정 성공·테스트 통과를 말하기 전에 `verification-before-completion`에 따라 이번 작업의 검증 명령을 실행하고 전체 출력과 종료 코드를 확인한다. 실행하지 못한 검증은 미확인으로 보고한다.
- 외부 스킬은 이 저장소의 작업 규칙을 보완한다. 원문의 영어 응답 지시나 자동 커밋·설정 변경 제안보다 한국어 작성, 요청 범위, 사람의 설계 결정, 커밋·푸시·배포 제한을 우선한다.
- 외부 원문과 부속 파일은 출처·라이선스를 보존한다. 프로젝트별 적용 조정은 원문을 고치지 않고 `agent-skills.md`에 적는다.
