# 예술in 공고별 MVP 평가표

현재 `vid`는 `https://yesulin.art/posts/{vid}`의 게시글 번호다. 이전 OTR 기준 시험 기록과 조사 번호는 과거 근거이며, 예술in 번호와 같다고 가정하지 않는다.

목표: 최신 공고부터 지원 링크를 만들고, 실제 모바일에서 지원자가 **제출 가능한 파일을 완성하는지** 확인한다. 운영자의 수동 정의 정확도와 제품 동작을 함께 평가하는 표이며, AI 자동 작성 성능 측정은 아니다.

## 기록 방법

- 회차 / 날짜: ___ / ___ · 시작 vid: ___ · 배포 커밋: ___
- 기기 / OS / 브라우저: ___ · 네트워크: ___ · 공통 시험 프로필: ___
- vid를 하나씩 줄이며 확인한 공고를 모두 기록한다. 삭제·중복·마감·배우 모집 아님은 `제외`와 이유를 적는다. DOCX 등 미지원 형식이나 구현 한계 때문에 못 만든 배우 모집 공고는 제외하지 않고 `불가`로 남긴다.
- 결과는 `O` 통과 / `X` 실패 / `?` 미확인 / `—` 해당 없음. 실패한 첫 결과를 고쳐 쓰지 말고 `X→O`와 수정 횟수를 적는다.
- 운영자 예시 값은 칸 위치 확인용이다. 배우 작성 시간은 공개 링크의 빈 화면에서 합성 프로필로 직접 입력하며 잰다. 실제 개인정보·사진·토큰·완성본 작업 URL은 이 문서에 기록하지 않는다.

## 공고별 기록 — 한 공고에 한 줄

| 기준 | O를 주는 조건 |
|---|---|
| A 요구 반영 | 공고 본문·이미지·첨부를 대조해 필수 질문, 선택지, 사진 수, 제출 형식·파일명·수신처·마감 안내에 누락이 없다. 표준 양식 사용이 해당 공고 요구와 맞는다. |
| B 공개·입력 | 운영자 테스트 후 공개한 링크가 새 탭에서 열리고, 휴대폰에서 필수 입력·선택·사진 업로드·누락 안내가 작동한다. |
| C 결과 문서 | 요청된 HWP/PDF를 내려받아 열었을 때 모든 값·체크·사진이 올바른 칸에 있다. 줄바꿈, 긴 자기소개, 경력 줄 추가에도 잘림·겹침·누락이 없고 원본 안내·서식이 보존된다. HWP는 한글 앱에서 확인한다. |
| D 수정·재생성 | 이름·선택지·사진을 바꿔 다시 생성했을 때 미리보기와 새로 받은 파일 모두 최신 값이다. 경력이 있으면 기본 줄 수를 넘겨 추가하고 확인한다. 별도 탭의 다른 시험 지원서와 결과가 섞이지 않는다. |
| E 제출 확인 | 해당 공고의 제출 방식·파일명·첨부 형식을 충족한다. 이메일 공고는 휴대폰에서 메일 앱으로 넘어가 **첨부파일까지** 확인하고, 본인 테스트 주소로 보내 받은 파일이 열린다. 메일 앱이 열리는 것만으로 O를 주지 않는다. |

E는 실제 모집처에 시험 메일을 보내지 않고 본인 주소에서 확인한다. 별도 웹폼·추가 영상 등 외부 단계는 문제 칸에 적고, 그 단계까지 확인하지 못하면 `?`로 남긴다. C에서 한글 앱 확인이 필요한데 못 했다면 역시 `?`다.

시간은 다음 구간을 잰다. 준비 시간에는 공고 확인, 정의 작성, 오류 수정까지 포함한다.

- **준비분**: 공고를 처음 열기 → 검증을 끝내고 지원 링크 공개.
- **작성분**: 준비된 합성 정보·사진을 가지고 모바일 공개 링크 열기 → 첫 생성 버튼 누르기. 생성 대기·메일 조작 시간과 분리한다.
- **생성초**: 생성 버튼 누르기 → 미리보기와 필요한 파일을 받을 수 있는 상태. 실패하면 `실패`로 적고 성공 시간 평균에서 숨기지 않는다.
- **첫 성공**: 첫 생성 결과가 C를 통과했는지 O/X. 생성 전 설정 오류도 문제 칸에 별도 기록한다.

최종 판정은 `통과 / 실패 / 미확인 / 불가 / 제외`. 필요한 A~E가 전부 O일 때만 통과다. 미지원·요구사항 표현 불가는 `불가`, 동작 오류는 `실패`, 남은 확인이 있으면 `미확인`이다. `—`로 판정할 때는 해당 없음의 이유를 적는다.

## 회차 집계

| 지표 | 계산 / 기록 | 이번 결과 |
|---|---|---|
| 공고 대응률 | 공개 링크를 만든 공고 ÷ 유효 배우 모집 공고. 유효 공고에는 미지원·불가 공고도 포함 | / = % |
| 제출 가능률 | 최종 통과 공고 ÷ 유효 배우 모집 공고. 미확인도 분모에 남김 | / = % |
| 최초 문서 성공률 | 첫 성공 O ÷ 첫 생성을 시도한 공고. 오류·사진 누락 실패도 포함 | / = % |
| 운영 준비 시간 | 완료 건의 중앙값 / 최댓값(분), 불가·중단 건 수와 투입 시간 별도 | / 분; 중단 건 / 분 |
| 모바일 작성·생성 시간 | 성공 건의 작성분·생성초 각각 중앙값 / 최댓값, 실패 건 수 별도 | 작성 / ; 생성 / ; 실패 건 |
| 반복 문제 | 가장 자주 실패한 A~E, 양식 형식, 원인과 건수 | |

HWP/HWPX 원본과 표준 양식은 나눠 집계한다. 한 공고를 여러 기기로 반복한 경우 공고 수는 중복 계산하지 말고 기기별 결과를 별도 행에 적는다. 회차 전체를 통과하려면 대상으로 정한 기기에서 모두 확인한다.

처음 10건은 시간·실패 원인을 파악하는 예비 평가로 삼고, 그 결과를 보고 다음 회차의 목표 시간과 성공률을 정한다. 운영자 본인의 시험은 기능 검증이다. 실제 사용성 판단은 처음 쓰는 배우에게 같은 과제를 맡겨 도움 요청·중단·소요 시간을 추가로 확인한다.
